# hotelbot

Telegram-бот, который с помощью Claude ведёт переписку с отелями по почте: задаёт вопрос (например, есть ли номера с джакузи и какая скидка), отвечает на их вопросы, дозапрашивает недостающие детали и по команде присылает сводку для выбора лучшего предложения.

Вы общаетесь только с ботом в Telegram. Письма уходят с обычного почтового ящика по SMTP, ответы читаются по IMAP. Никаких облачных консолей и OAuth: нужны только адрес и пароль приложения.

## Как это работает

```
Вы ── Telegram ──▶ бот-сервис ──▶ Claude (инструменты) ──▶ SMTP ──▶ отели
                      │  ▲                                          │
                      │  └──────────── опрос IMAP ◀─────────────────┘
                      └──────▶ файлы данных (переписка, факты, вопросы)
```

* Сервис делает только исходящие соединения (Telegram long polling, Anthropic API, IMAP, SMTP). Входящие порты не нужны.
* Задачи выполняются строго по одной (одна очередь), поэтому состояние не портится.
* Почта опрашивается без участия модели; Claude запускается только когда есть новое письмо или ваше сообщение.
* Ответы сопоставляются с отелями по заголовкам `In-Reply-To` / `References` (даже если ответил другой сотрудник отеля с другого адреса) и по адресу отправителя.
* Claude не помнит прошлых запусков: вся память в файлах (`facts.md`, `hotels.json`, `hotels/<id>.md` и др.).
* Переписка с каждым отелем сохраняется кодом в текстовый файл `hotels/<id>.md`, а не пересказом модели.

## Команды в Telegram

Обычный текст идёт Claude. Служебные команды обрабатывает код:

| Команда | Что делает |
|---|---|
| `/send` | отправляет утверждённый вами шаблон первого письма всем отелям из черновика |
| `/cancel` | отменяет черновик рассылки |
| `/check` | проверяет почту прямо сейчас |
| `/hotels` | список отелей и статусов |
| `/transcript название` | присылает переписку с отелем |
| `/status` | состояние сервиса, очередь, счётчики отправок |

Типичный сценарий: пишете «спроси у отелей, есть ли номера с джакузи» и присылаете email, бот предлагает шаблон, вы утверждаете его командой `/send`. Дальше на ответы отелей бот отвечает сам, а вопросы, на которые нет ответа в фактах, передаёт вам. Просите «уточни про завтрак», и он допишет только тем, кому ещё не задавал этот вопрос. Просите «что по отелям», и получаете сводку.

## Защита от ошибок и злоупотреблений

* Команды принимаются только от вашего Telegram-аккаунта (`OWNER_TELEGRAM_ID`), сообщения других игнорируются.
* Claude не задаёт адрес получателя: он указывает id отеля, а адрес берётся из реестра. Отели в реестр попадают только с адресами, которые дословно есть в вашем сообщении, и только в ответ на ваше сообщение, но не в ответ на письмо отеля.
* Первая рассылка уходит только после вашей команды `/send`, текст отправляет код, а не модель.
* Лимиты писем в час и в сутки, блокировка повторной отправки одного текста тому же отелю.
* Почту бот только читает (папка INBOX открывается только для чтения) и отправляет. Удалять и перемещать письма он не может.
* Тексты писем отелей передаются Claude как недоверенные данные; в системном промпте запрещено выполнять содержащиеся в них инструкции, раскрывать условия одних отелей другим и подтверждать бронь, предоплату, залог, личные данные.
* Режим `DRY_RUN=1` (включён по умолчанию): письма записываются в переписку, но не отправляются. Включайте реальную отправку, только когда проверите работу на тестовом адресе.
* Пароли и ключи лежат в `/etc/hotelbot.env` (права 600), в репозиторий не попадают и в журнал не пишутся.

## Установка

Нужны: сервер с Ubuntu 24.04 (Python 3.12 уже есть), аккаунт Telegram, почтовый ящик с доступом по IMAP/SMTP, ключ Anthropic API. Пароли и ключи вводите только в файлы на сервере и никому не отправляйте.

### 1. Telegram-бот

1. В Telegram откройте @BotFather, команда `/newbot`, получите токен.
2. Напишите своему новому боту любое сообщение (например, `/start`).
3. Узнайте свой числовой id: на своём компьютере выполните `curl "https://api.telegram.org/bot<ТОКЕН>/getUpdates"` и найдите `"from":{"id":...}`. Это значение `OWNER_TELEGRAM_ID`.

### 2. Почтовый ящик

Подойдёт любой ящик, у которого есть IMAP/SMTP и пароль приложения. Проверенные на момент написания сведения:

| Провайдер | IMAP | SMTP | Замечания |
|---|---|---|---|
| Яндекс Почта | `imap.yandex.ru`, 993 | `smtp.yandex.ru`, 465 (или 587) | рекомендую, см. ниже |
| Свой домен или хостинг | из документации хостера | из документации хостера | логин обычно полный адрес |
| Mail.ru | `imap.mail.ru`, 993 | `smtp.mail.ru`, 465 | в феврале 2026 писали, что доступ из почтовых клиентов тестово делают платным (подписка Mail Space); проверьте, получится ли создать пароль внешнего приложения |
| Outlook.com (личный) | не рекомендую | | Microsoft убирает вход по обычному паролю, останется только OAuth, которого здесь нет |

Яндекс Почта:

1. В настройках почты откройте «Почтовые программы» и включите доступ по IMAP с сервера `imap.yandex.ru`; убедитесь, что включена опция «Пароли приложений и OAuth-токены».
2. Создайте пароль приложения на странице паролей приложений вашего Яндекс ID (тип «Почта»). Он показывается один раз.
3. Логин для входа (`MAIL_USER`) — часть адреса до `@`.

У бесплатных ящиков есть свои лимиты на отправку и антиспам-фильтры. Лимиты бота по умолчанию консервативные; если первое письмо отелю попало в спам, это нормально для нового ящика: проверьте папку «Спам» тестового получателя.

### 3. Сервер

```bash
# код (deploy key уже добавлен в репозиторий)
sudo install -d -o hotelbot -g hotelbot /opt/hotelbot
sudo -H -u hotelbot git clone git@github.com:mvladlen/mailer.git /opt/hotelbot
sudo -H -u hotelbot python3 -m venv /opt/hotelbot/.venv
sudo -H -u hotelbot /opt/hotelbot/.venv/bin/pip install /opt/hotelbot

# каталог данных
sudo install -d -m 700 -o hotelbot -g hotelbot /var/lib/hotelbot

# настройки и секреты
sudo install -m 600 -o root -g root /dev/null /etc/hotelbot.env
sudo nano /etc/hotelbot.env        # заполните по образцу .env.example

# запуск
sudo cp /opt/hotelbot/deploy/hotelbot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now hotelbot
journalctl -u hotelbot -f
```

Напишите боту `/status`: он должен ответить, что режим проверки включён. Затем `/check`: если логин или пароль почты неверны, в журнале появится «ошибка опроса почты».

### 4. Проверка и боевой режим

1. Оставьте `DRY_RUN=1`, дайте боту задачу с вашим тестовым адресом, убедитесь, что шаблон и переписка выглядят правильно (`/transcript`).
2. Поставьте `DRY_RUN=0` в `/etc/hotelbot.env`, выполните `sudo systemctl restart hotelbot`, повторите на тестовом адресе, который отвечает вам самому, и проверьте, что ваш ответ пришёл боту (`/check`).
3. Только после этого давайте адреса настоящих отелей.

### Обновление

```bash
sudo -H -u hotelbot git -C /opt/hotelbot pull
sudo -H -u hotelbot /opt/hotelbot/.venv/bin/pip install /opt/hotelbot
sudo systemctl restart hotelbot
```

## Данные

Каталог `HOTELBOT_DATA_DIR` (по умолчанию `/var/lib/hotelbot/data`) нужно периодически копировать в резерв: в нём вся история.

```
facts.md          факты по поездке и ваши ответы на вопросы отелей
hotels.json       реестр отелей, предложения, статусы вопросов
questions.json    вопросы, которые выясняем у отелей
pending.json      вопросы, ожидающие вашего ответа
batch.json        черновик первой рассылки (до /send)
sent.jsonl        журнал отправок
hotels/<id>.md    переписка с каждым отелем
```

## Ограничения

* Клиент IMAP/SMTP проверен тестами на подменённых `imaplib`/`smtplib`, но не против живых серверов провайдеров: первый боевой прогон делайте в режиме `DRY_RUN=1`, а затем на тестовом адресе.
* Ответ владельца на вопрос отеля и новую задачу различает Claude по контексту; при сомнении он должен переспросить.
* Просматриваются письма за последние 14 дней. Если отель ответил позже, ответ нужно переслать боту вручную (или написать об этом боту).
* Копия отправленного письма в папку «Отправленные» зависит от провайдера; полная переписка в любом случае лежит в `hotels/<id>.md`.
* Сравнение предложений делает модель по извлечённым полям; перед решением сверяйтесь с перепиской (`/transcript`).
